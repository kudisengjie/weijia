## 已确认范围

1. 字体恢复到扩大前的紧凑级别，继续用微软雅黑；不通过整体 zoom/transform 缩放界面。草稿正文 12px、辅助 10–11px、模块标题 14px、页标题 22px；表格密度回到早期版本。不得为减少换行裁掉必要信息。
2. 普通 SaaS 账号必须有自己的设置；开通子账号、积分调整和续期移出普通设置，只允许站点总账号。
3. 登录页不能在未主动输入密码的情况下自动跳走，优先解决该交互与会话问题。
4. 用户已明确确认：每个账号最多 5 个独立任务工作区并行；每个工作区一份 Excel，可含多行任务，不是单份 Excel 内同时执行 5 行。
5. 保留冰蓝色与零雪人物，可缩小并迁移人物位置；左下角“独立会话”说明替换为“新建任务”。
6. 本阶段先给可选择的草稿，不把原型按钮当成真实功能上线。文章本地保存路径仍为先前明确延期的独立事项。

## 两套布局

### A：紧凑任务控制台（推荐首页）

左侧 180px 导航，主区是五个任务的列表。每行展示：工作区名、模型、状态、完整文章数、预扣积分、查看/暂停/继续。列表下方显示当前选中的阶段与已保存文件；人物缩为右下角小型品牌陪伴区。取消巨大欢迎标题、超大上传面板、整列人物状态舱。

适合同时追踪多个客户或品牌；文件长名称在详情完整显示，状态和数值不压成多行。左下角显示“＋ 新建任务 / 5 个名额占用情况”，满额给出原因，而不是看起来按钮坏了。

### B：多任务页签工作台（推荐详情）

顶部并排五个工作区页签，每个页签显示简短名称、状态和进度；下方只展示当前任务，内部为“资料与任务 / 运行进度 / 文章文件”。文章预览使用宽主区，右侧是约 232px 的紧凑任务状态，人物降为 64px 的辅助卡。

适合关注当前文章内容。切换页签只是切换视图，不能取消或重启其他工作区的请求。窄屏页签横向滚动，内容单列；不把五份完整表格挤在同一个屏幕。

建议组合：A 为默认首页，点击“打开”进入 B；也可按用户选择只采用其中一套主要视图。

## 目录式设置与权限

普通个人设置目录：模型与 API、登录与安全、积分与有效期、联系与续费。现有 API 录入与测试能力保留，仅拆分页面。

独立管理中心目录：子账号管理、积分调整、有效期与续期、IMA 凭据、共享缓存、操作记录。只有 owner 可看到入口；member 及 admin 都不能使用这些 owner-only 功能。后端权限按服务端账号身份判断，不能接受前端传来的角色作为授权。

创建/修改账号用专属页面或抽屉，先选择账号再操作；积分与续期提交前清楚列出目标账号、变更前后数值。使用已有微信二维码，不增加在线支付。不要把 IMA 密钥或其他账号的数据发送给普通成员浏览器。

现有代码证据：runtime.js 已按 subscription.role 隐藏 #tenant-admin 与 .ima-admin，app.py 的相关端点已有 require_owner 校验。问题主要是总账号下所有表单仍堆在一页；此阶段不是假设后端完全没有权限控制。

## 登录诊断与整改提案（优先实施）

已查明的代码路径：

- security.py 的 SESSION_TTL 为 7 天；app.py 登录 Cookie 的 max_age=604800。
- runtime.js 初始化直接请求 auth/session，任何成功响应都进入 enter()，没有等待用户提交密码。
- AuthService.login 仍验证密码；repository.get_session 只接受未撤销且未到期的会话。不能仅凭自动跳转就声称陌生人已绕过后端认证。
- 前端启动会话请求和手动登录可能同时存在，没有统一的认证操作代数；较早的失败响应可能晚到并清掉新登录，较早的成功响应也可能干扰新的退出流程。这是需专项复现/补测的竞态风险，不是已确认生产发生的事实。

新增本机受控响应诊断已复现：auth/session=401 时保持登录页；=200 时密码框为空、未发 auth/login 就显示工作台。此测试只证明当前前端自动恢复路径，不证明生产账号安全、实际 Cookie 状态或修复成功。

推荐登录规则：

1. 登录入口始终显示表单；即使有旧 Cookie，也不自动提交/跳转，用户输入密码后点击登录。
2. 登录工作台后，同一页面刷新可在服务器验证有效会话后恢复进度；从官网/登录入口重新进入仍需要密码。新标签页直接访问工作台是否也强制重新验证应在实施前固定规则，不能仅用本地“已登录”布尔值充当认证。
3. 不再默认保留 7 天自动登录。推荐短会话及服务端空闲超时（拟定绝对 8 小时、交互空闲 30 分钟，运行状态轮询不算用户活动）；超时锁定界面，后台任务的执行授权与已登录页面寿命分开。
4. 认证流程统一为 checking / logged-out / submitting / authenticated / locked 状态；先确认 authenticated === true 和响应结构，再进入。退出或重新登录时作废旧请求，旧响应不能覆盖新状态。
5. 登录成功轮换会话；退出时撤销服务端会话并清理前端敏感视图。保留 HttpOnly / Secure / SameSite、CSRF、no-store 和登录限流；owner 调整积分、续期、开通账号及修改 IMA 前要求近期密码验证。
6. 认证服务异常停在可重试的明确页面，不把错误解释为已登录；业务设置读取失败与认证失败分开呈现。

会话超时和退出撤销依据：[OWASP Session Management Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)。具体时长是本项目建议，不是 OWASP 强制值。

不得把前端隐藏页面作为安全修复。必须验收：空密码/错误密码/无 Cookie/过期 Cookie/撤销 Cookie/旧响应晚到/重复点击/退出后后退/新标签页/刷新/不同账号切换，确认 UI 和受保护接口都符合约定。

## 五个工作区的执行设计

当前限制不止在页面：runtime.js 只有 activeBatch 与 driving，app.js 只有一组 currentTask/currentCompanies；BatchService._create 使用 has_active_batch 拒绝第二个活动批次。必须一起改，不能只打开前端限制。

- 每个工作区都有独立 workspaceId、草稿、Excel、公司资料、选定模型、requestId、batchId、状态与文件。切换视图不切换运行对象。草稿与解析结果持久化也必须账号隔离、遵守现有服务端加密规则，不能把资料混入公共 IMA 缓存。
- 每账号最多五个未结束工作区；草稿/运行/暂停占位，已完成/已取消归档释放名额。前端显示上限，服务端在账号锁/事务内确认数量并分配名额；多设备、多标签页同时提交也只能有五个。具体错误码统一为 WORKSPACE_LIMIT_REACHED。
- 不同工作区可在启动前选择不同的已配置模型；启动时保存不可变模型与 Key 快照。运行/暂停中不能换模型，也不能用修改全局设置的方式替换活动任务的快照；新草稿可编辑自己的模型。
- 每个工作区内部先保持逐行、逐阶段执行，账号级最多五个在途上游请求，避免 5 工作区 × 每份 5 行变成 25 并发。额外设置站点总体并发与厂商速率上限；HTTP 429、鉴权失败、余额不足须明确反馈，不能用无限重试伪装稳定。
- IMA 沿用现有全站加密缓存和显式清除机制，缓存命中不再获取相同资料；缓存缺失争用使用已有锁并复查，避免并行重复取。每批次固定缓存代数。
- 积分仍为每条有效 Excel 行 1 分，非每个工作区 1 分；在各批次事务里预扣并写幂等台账，一行所有要求的文章文件完整保存才结算。哪一行失败就返还对应 1 分；其他行及其他工作区继续。总预扣不能透支账号余额。
- 每个工作区独立暂停/继续/取消/异常提示/文件清单；不可因当前页面显示另一个任务而错写文件或给错误批次退款。
- 持久队列和带租约的 worker 是“关页面后仍继续”的必要部署项。当前生产 worker 主机/调度未确认，不擅自购买资源；保持 EdgeOne + Python + Neon 路线，先落实可用执行承载再验收后台并行。仅浏览器 Promise.all 不能当作持久并行交付。
- 模型或网络失败不可能保证永不发生；交付标准是已输出文件不丢、失败可见、退款准确、结果不明不重复扣费重发、其他任务不被拖停。

## 实施顺序与验收门槛

1. 用户选择 A / B / A+B，并确认登录规则；先单独修复认证自动跳转与竞态，建立真实浏览器加后端会话回归。
2. 恢复紧凑字体；拆分个人设置与 owner 管理中心，验证 member/admin 直接请求 owner 接口返回 403。按选定方案做桌面/移动布局验收。
3. 持久化五工作区、账号级并发限制与运行调度；采用真实 PostgreSQL 检查同时创建第六个、并发扣分、五路独立文件与退款、暂停隔离、重复执行器认领。
4. 本机浏览器验证五个工作区切换；故障注入一条失败/一工作区断连/Key 失效，确认其他任务继续、文章可下载且仅失败行退款。
5. 确認生产调度后，经用户许可用自己的 Key 做少量真实上游任务验证，再推送已验收的版本。构建成功不等于线上任务成功。
