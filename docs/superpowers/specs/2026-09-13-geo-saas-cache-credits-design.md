# GEO SaaS 共享 IMA 缓存、积分与双执行器设计

> 状态：设计已确认，等待拆分实现计划。本文不包含任何密钥、密码、管理员口令或真实账号信息。

## 目标

在现有 EdgeOne Pages + Python Cloud Functions + Neon PostgreSQL 基础上，增加可扩展的 SaaS 多租户能力：IMA 使用站点所有者凭据并按全站共享缓存复用；每个子账号自行接入模型 API Key；任务按有效期和积分运行；任务模型在批次内固定；EdgeOne 和独立 Worker 共用同一套持久状态机，保证刷新、网络中断或关闭网页后不会重复扣分、重复调用或丢失文章。若某条任务没有形成完整文章文件，则自动返还该条任务的 1 个积分。

## 约束与不变规则

- IMA 凭据只属于平台所有者，永不下发给子账号或浏览器。
- IMA 缓存按整个站点共享，缓存内容只作为证据输入，不允许子账号直接浏览其他租户的数据。
- 子账号模型 API Key 独立保存、服务端加密，模型供应商请求必须使用任务所属子账号的 Key。
- 一个有效 Excel 任务行对应 1 个积分；空格式行不计费。
- 计费、返还和重试均使用幂等流水号，任何网络重放都不能重复扣分或重复退款。
- 批次创建时固定厂商、模型 ID、密钥快照和 IMA 缓存版本；运行中的批次不受设置页后续改动影响。
- 网站不提供在线支付或充值接口，只展示平台所有者提供的微信二维码和联系说明。
- 到期账号可以查看历史结果，但不能创建、恢复或继续执行任务；续期后立即恢复。
- 不自动重试外部 IMA 或模型请求；失败必须持久化并由恢复流程从安全边界继续。

## 租户与权限模型

### 角色

- `owner`：平台所有者，管理租户、有效期、积分、IMA 凭据、共享缓存、二维码和审计记录。
- `tenant_admin`：可管理自己租户的成员和模型设置，但不能读取 IMA 凭据、修改共享缓存或给自己增加积分。
- `member`：只能使用所属租户分配的积分和模型设置。

所有业务表必须带 `tenant_id` 或通过用户到租户的关系约束访问范围。owner 的管理接口使用独立权限检查，不依赖前端隐藏按钮。

## 全站 IMA 缓存

### 数据结构

Neon PostgreSQL 新增以下逻辑表，实际名称可在实现计划中固定：

- `ima_cache_meta`：单例缓存代次、当前凭据版本、最后清除时间、统计信息。
- `ima_knowledge_bases`：知识库名称到 IMA ID 的映射，按缓存代次保存。
- `ima_rule_documents`：copilot 规则文件和记忆档案正文，正文加密并带 SHA-256、长度和媒体 ID。
- `ima_search_cache`：`knowledge_base_id + normalized_question + cache_generation` 的检索结果及媒体 ID 列表。
- `ima_media_cache`：媒体 ID、标题、类型、正文密文、正文哈希和读取时间。
- `ima_cache_locks`：按唯一缓存键协调并发 miss，避免多个子账号同时重复请求 IMA。

所有正文和搜索证据使用服务端主密钥加密；缓存键、哈希、长度和状态可用于诊断，但不暴露原文给普通租户。

### 获取算法

1. 批次创建时解析有效任务行，按 `(knowledge_base, question)` 去重，只计算真实任务数量。
2. 先读取当前共享缓存代次；命中知识库目录、规则、搜索结果和媒体正文时不得访问 IMA。
3. 缺少目录时只获取知识库目录；缺少规则时只获取必需的生成、审核和记忆文档。
4. 缺少某个问句的检索结果时才访问该知识库，并最多保留规定数量的候选证据。
5. 缺少媒体正文时才读取该媒体；同一媒体正文被多个任务引用时只读取一次。
6. IMA 请求成功且正文通过校验后才写入缓存；失败、空内容、格式错误和超限内容不得写入“成功缓存”。
7. owner 点击清除缓存时递增 `cache_generation`，旧缓存保留审计信息但不再被新任务使用；下一次 miss 才重新获取。

缓存 miss 的并发流程使用数据库唯一键和短期锁：拿到锁的执行器请求 IMA，其他执行器等待后重新读取缓存；持锁执行器失败时释放锁，不留下假数据。

## 积分与失败返还

### 流水状态

每条任务都有独立的 `credit_reservation` 和不可变 `credit_ledger`：

- `reserved`：批次创建时锁定 1 个积分。
- `charged`：任务首次安全启动并进入执行后确认扣除。
- `refunded`：任务进入终态但未产生完整文章文件，自动返还 1 个积分。
- `released`：批次在任务尚未启动前取消或校验失败，释放预留积分。

幂等键使用 `(tenant_id, batch_id, task_index, operation)`，重试、刷新、Worker 接管和 EdgeOne 接管都只能产生一条流水。

### 完整文章文件定义

任务只有同时满足以下条件才算成功并保留积分扣除：

- 模型生成正文非空；
- 审核阶段通过；
- 文章记录已写入 Neon；
- 输出文件或可下载文章工件已写入存储并有非空大小、SHA-256 和完成状态；
- 批次状态和文章索引在同一个事务中提交。

如果模型调用失败、审核失败、修订失败、服务中断、文件写入失败或最终工件校验失败，则该任务只标记为 `failed`，并将其 1 个积分转为 `refunded`。同一批次的其他成功任务不受影响。

下载失败不退款：只要服务端已保存完整工件，用户可以重新下载。用户重新运行已退款任务时，需要重新预留 1 个积分；恢复操作本身不重复扣除同一运行的积分。

## 订阅有效期与提醒

租户订阅保存 `starts_at`、`expires_at`、`status` 和审计字段，统一使用 Asia/Shanghai 展示、UTC 存储。创建、恢复、扣分和 Worker 取任务前都检查有效期。

- 到期前 7/3/1 天在工作台和管理员页显示提醒。
- 到期后禁止新批次、继续任务和 Worker 执行；历史文章仍可读、可下载。
- owner 修改续期日期后写入审计流水，权限即时恢复。

## 模型 Key 与批次锁定

模型设置属于租户，不属于全站。创建批次时把模型配置快照写入受保护的批次凭据表：供应商、模型 ID、密钥密文、配置哈希。后续每一步只读快照，不再读取当前设置。

设置页可以修改“新任务默认模型”，但正在运行的批次始终显示“已锁定：供应商 · 模型”。后端拒绝任何试图改写批次模型快照的请求；模型切换只对新批次生效。

## A+B 双执行器

### 方案 A：EdgeOne 执行器

EdgeOne API 负责登录、管理接口、批次创建、短步骤执行、状态查询和恢复。每个请求只执行有限步骤并在每一步完成后提交 Neon 状态，避免超时丢失。页面打开时自动轮询并在中断后从最后一个安全序号继续。

### 方案 B：独立 Worker

独立 Worker 使用同一 Python 业务包和同一 Neon 数据库，通过 `jobs`/`batch_claims` 领取待执行步骤：

- `FOR UPDATE SKIP LOCKED` 或等价租约保证单步只有一个执行器；
- 任务包含 `lease_until`、`attempt`、`next_run_at` 和 `last_error`；
- EdgeOne 和 Worker 使用相同的幂等键、缓存锁和积分流水；
- Worker 超时或崩溃后租约到期，下一次只能从已提交的步骤继续；
- 浏览器关闭后 Worker 仍可完成任务；页面重新打开只需读取状态和下载结果。

EdgeOne-only 环境作为无 Worker 时的降级执行器；启用 Worker 后由 Worker 优先领取，EdgeOne 只负责唤醒、查询和人工恢复。

## 管理界面与微信二维码

owner 后台增加：租户列表、子账号有效期、积分余额/流水、缓存统计与清除、失败任务退款记录、Worker 健康状态。普通租户增加：剩余积分、到期日期、固定模型状态、任务失败退款提示。

微信二维码作为静态站点资源或 owner 可替换的受保护资源展示在“积分不足/账号即将到期/账号已到期”提示中，文案明确为“请联系平台所有者处理”，不实现在线支付、不收集微信支付凭据。

## 验收标准

- 两个不同子账号运行同一问句时，第二个任务命中共享缓存，不产生对应的 IMA miss 请求。
- 清除缓存后下一次 miss 才重新访问 IMA；未使用的知识库和媒体不被读取。
- 5 条有效任务创建时预留 5 点；成功 4 条、失败 1 条后余额净减少 4 点，并出现 1 条退款流水。
- 同一失败任务恢复、刷新或 Worker 接管不会再次扣除或再次退款。
- 任务运行期间切换设置不会改变批次模型或 Key；完成后新批次可以选择新模型。
- 关闭浏览器后 Worker 仍能完成文章；没有 Worker 时重新打开页面可以从安全序号恢复。
- 到期账号无法创建/继续任务，续期后立即可用；所有管理操作有审计记录。
