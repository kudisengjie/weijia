# GEO PC 端可读性与运行可靠性设计

## 背景

线上工作台已经可以登录并读取文件，但 PC 端大量正文、状态和表格文字仍使用 8–11px，阅读成本过高。页面还存在三个会误导或阻断用户的问题：顶部 IMA/模型徽标没有跟随服务端配置状态更新；Excel 中仅用于格式的空白行被计入 100 行上限；部分模型厂商的默认模型 ID、官方接口地址或鉴权方式已经变化。

## 目标

- 保持移动端现有布局，重点提升 861px 以上 PC 端的字号、行高、间距与按钮状态辨识度。
- 让顶部徽标、创作准备区、设置页和右侧状态舱展示同一份服务端配置状态。
- 任务表只提交有内容的行，不能因为 Excel 的空白格式行误触 100 行限制。
- 保留现有 API Key 接入界面和保存方式，仅更新已确认的官方模型目录与请求适配。
- 不在前端、文档或 Git 中写入任何密钥、密码或数据库连接串。

## 设计

### 1. PC 字体系统

全局字体优先使用 `Microsoft YaHei`。移动端已有规则不改；在 `min-width: 861px` 的桌面媒体查询中统一放大微型文字：辅助/状态文字至少 12px，正文、表单、按钮和导航 14–15px，卡片标题 16–18px，页面标题保持 32–40px。表格提升至 13px，并增加单元格内边距与行高。顶部品牌标题和模型/IMA 徽标同步放大，但不得超过页面主标题。

运行按钮使用两种明确状态：可运行时为深蓝底白字并允许点击，禁用时才显示灰色和禁止光标。

### 2. 状态单一来源

登录后 `/api/settings` 是连接状态的唯一来源。HTML 只提供带数据属性的占位节点；`renderConnections()` 同时更新顶部模型状态、顶部 IMA 状态、创作准备区、设置摘要与右侧状态舱。`已配置` 只表示凭据存在；模型真实可用性仍由现有“测试已保存模型”按钮的小请求确认。

### 3. Excel 有效行规范化

工作簿读取后，逐行把单元格转成字符串，并删除所有整行为空或只包含空白字符的行。内部有内容的行顺序不变，标题行仍是第一条有效行。预览、状态统计和批次提交都使用同一份规范化数据，因此前端与后端的 100 行限制一致。

后端仍保留独立校验，防止绕过浏览器直接提交超量数据。

### 4. 模型目录与厂商适配

现有“选择厂商/模型 + API Key + 可选实际模型 ID + 保存/测试/移除”交互保持不变。目录只采用厂商官方资料可确认的 ID；历史上由用户保存的自定义模型 ID 继续优先使用。

- 腾讯混元：修正为腾讯云 MaaS TokenHub 官方域名，保留 Hy3 / Hy4 Preview。
- 通义千问：保留 Qwen3.8 Flash / Max。
- 豆包：保留 Seed 2.0 Lite / Pro。
- DeepSeek：保留 V4 Flash / Pro。
- MiniMax：使用 M2.7 / M3，并调用中国开放平台当前的 OpenAI 兼容接口。
- 智谱 GLM：使用 GLM-5.3 Flash / GLM-5.3。
- Kimi：界面保留用户指定的 K2.7 Code / K3；开放平台请求 ID 使用 `kimi-k2.7-code` / `kimi-k3`，并切换到当前 Kimi API 域名。
- Xiaomi MiMo：保留 V2.5 / V2.5 Pro，改用官方 OpenAI 兼容的 Bearer 鉴权。

MiniMax、Kimi 与 MiMo 使用其官方文档要求的 `max_completion_tokens`；混元使用不低于官方建议的输出额度，避免思考模型因额度过小截断。生成请求不自动重试，避免重复扣费或重复生成。

## 验证

- Node 单元测试覆盖模型目录、状态节点、桌面字体规则和 Excel 空白行清理。
- Python 单元测试覆盖八个厂商的接口地址、鉴权、请求字段及错误处理。
- 执行生产构建，确认 `dist` 只包含公开静态文件并同步最新 bundle。
- 没有用户的各厂商真实密钥时，不宣称所有模型线上调用成功；线上用户可通过现有“测试已保存模型”逐个执行真实小请求。
