# 官网统一导航与零雪 GEO 入口设计

日期：2026-08-27
状态：用户已确认设计方向，待实施计划
视觉方案：A「冰晶胶囊入口」

## 1. 背景

官网当前在桌面端使用固定白色半透明导航，六个内容栏目位于品牌标识和语言切换之间。零雪 GEO 静态工作台目前只有页脚入口，用户要求在顶部导航增加第二个明显入口，并提升导航的整体视觉质量、移动端适配和主页面之间的一致性。

现状检查还发现：具备中英切换的主页面使用同一类导航结构，但代码分别写在各 HTML 文件中；文章详情页使用另一套较精简导航。用户明确要求文章详情页保持现状，因此本次不改文章页。

## 2. 目标

1. 在主页面顶部导航增加“零雪 GEO 程序”入口。
2. 入口在新标签页打开 `https://geo.lxue.xin/`，与现有页脚入口指向同一页面。
3. 统一七个主页面的导航结构、视觉层级、当前页高亮、响应式行为和菜单交互。
4. 桌面端保持紧凑、专业，不因增加入口产生换行、遮挡或横向溢出。
5. 移动端菜单容易阅读和点击，不发生栏目压缩、截断或错位。
6. 用自动检查防止后续只修改某个页面而破坏一致性。

## 3. 明确不做

- 不修改 `articles/` 下任何文章详情页的导航、语言按钮或正文。
- 不修改零雪 GEO 静态工作台的页面、上传预览能力或任务运行状态。
- 不接入 IMA、DeepSeek、数据库或登录系统。
- 不改变页脚入口的现有行为；本次只要求顶部入口使用新标签页。
- 不新增外部 UI 框架、图标库或构建系统。
- 不显示“外链”或箭头图标。

## 4. 页面范围

统一以下七个现有主页面：

- `index.html`
- `profile.html`
- `blog/index.html`
- `geo-guide.html`
- `insights.html`
- `support.html`
- `brand-facts.html`

共享资源范围：

- `style.css`
- `script.js`
- `i18n.js`
- 新增一个导航一致性验证脚本，放在 `tools/`。

## 5. 已比较的方案

### 方案 A：冰晶胶囊入口（采用）

普通内容栏目保持低干扰，零雪 GEO 作为独立雪蓝胶囊按钮，移动端使用整行工具按钮。入口辨识度、品牌感和触控体验最均衡。

### 方案 B：同级文字入口（不采用）

把零雪 GEO 当作第七个普通栏目。改动小，但桌面端更拥挤，工具属性不明确，移动端也不够醒目。

### 方案 C：双层工具导航（不采用）

增加独立顶部工具条。层级清楚，但会明显增加导航高度并压缩首屏，尤其不适合移动端。

## 6. 桌面端设计

排列顺序：

`品牌标识 → 首页 → 品牌详情 → 行业博客 → GEO指南 → GEO策略 → AI问答 → 零雪 GEO 程序 → English`

设计规则：

- 保留现有品牌标识与固定导航高度，不创建新的图片资产。
- 普通栏目使用统一圆角、字重和间距；当前页面以克制的浅蓝底和较高字重标识。
- GEO 入口使用雪蓝浅底、蓝色细边框、深蓝文字和现有雪花视觉语言，外观区别于普通栏目但不压过品牌标识。
- GEO 入口文字为“零雪 GEO 程序”；英文状态为“Lxue GEO Workbench”。
- GEO 入口不显示箭头提示。
- 当桌面宽度不足以稳定容纳所有项目时，导航提前进入折叠模式，不强行压缩文字、不换行。
- 滚动后的导航继续使用现有半透明背景和轻量阴影，不增加强烈发光或厚重阴影。

## 7. 移动端与中等屏幕设计

- 顶栏保留品牌标识和菜单按钮，内容不横向挤压。
- 菜单按钮使用真正的 `button` 语义，并包含 `aria-expanded`、`aria-controls` 和可读标签。
- 展开菜单后，六个内容栏目采用两列布局；当前页仍有明确高亮。
- “零雪 GEO 程序”放在栏目网格下方，占据完整一行，形成清晰的工具入口。
- 语言切换放在 GEO 入口下方的独立区域。
- 单个可点击区域至少 44×44 CSS 像素。
- 支持菜单按钮再次点击、点击导航项、点击菜单外部、按 `Esc` 关闭。
- 从移动端切回桌面宽度时自动清除菜单打开状态，避免残留遮罩或滚动锁定。

## 8. 链接与语言行为

顶部 GEO 入口：

```html
<a
  href="https://geo.lxue.xin/"
  target="_blank"
  rel="nofollow noopener noreferrer"
>
  零雪 GEO 程序
</a>
```

- 新标签页打开。
- 不显示箭头。
- 不在 JavaScript 中拼接目标地址，避免页面间出现不同 URL。
- 在 `i18n.js` 中增加中英文导航文案，沿用现有语言切换机制。
- 文章详情页不加入该入口，继续保持当前导航与语言支持范围。

## 9. 实现方式

采用“静态 HTML 明确存在 + 共享 CSS/JS 管理行为”的方式：

- 七个主页面直接写入相同的 GEO 导航元素，避免依赖 JavaScript 成功后才出现入口。
- `style.css` 统一控制桌面胶囊、折叠断点、移动端两列菜单和焦点状态。
- `script.js` 统一管理菜单展开、关闭、窗口宽度变化和无障碍属性。
- `i18n.js` 只增加 GEO 入口文案键，不改变其他页面内容。

未采用运行时完整注入导航，因为脚本延迟或失败会造成入口缺失和首屏闪动；未采用构建期模板，因为当前 EdgeOne Pages 直接部署静态文件，引入新构建链会增加部署风险。

## 10. 无障碍与可用性

- 所有链接和菜单按钮支持键盘聚焦，并具有清晰的 `:focus-visible` 状态。
- 菜单按钮状态与 `aria-expanded` 同步。
- GEO 入口的新标签行为通过可访问名称说明，但视觉上不增加用户明确拒绝的箭头。
- 颜色对比度不依赖浅色文字表达状态；当前页与 GEO 入口同时通过颜色、字重和边框区分。
- 在 `prefers-reduced-motion: reduce` 下禁用非必要过渡。

## 11. 验证标准

自动检查：

1. 七个主页面均包含且只包含一个顶部 GEO 入口。
2. 七个入口 URL、`target`、`rel` 和 i18n 键完全一致。
3. 七个页面的主导航项目顺序一致，只有当前页 `active` 状态不同。
4. 文章详情页未被修改。
5. 现有官网验证脚本全部继续通过。

官方 Google Chrome 人工与自动浏览器检查：

- 桌面：1440×900、1280×800。
- 中等屏幕：1024×768。
- 移动端：390×844、360×800。
- 检查导航无横向溢出、无文字截断、菜单开关正常、当前页高亮正确。
- 检查顶部 GEO 入口打开新标签页且地址为 `https://geo.lxue.xin/`。
- 检查七个主页面视觉一致，文章详情页保持原状。

## 12. 风险控制

- **风险：新增入口导致桌面导航拥挤。** 通过更早的折叠断点和紧凑间距处理，不缩小到难以点击。
- **风险：重复 HTML 后续漂移。** 通过导航一致性验证脚本阻止漏改。
- **风险：移动菜单状态残留。** 在外部点击、`Esc`、页面跳转和窗口变化时统一复位。
- **风险：误改文章页。** 实施前后记录 `articles/` 差异，验收要求该目录无改动。
- **风险：影响 EdgeOne 静态部署。** 不引入依赖和构建步骤，保持现有发布方式。

只有同时满足以下条件才算完成：

- 七个主页面顶部导航视觉和结构统一。
- PC、中等屏幕和移动端均无布局问题。
- GEO 入口按约定新标签打开正确域名且无箭头。
- 文章详情页无变化。
- 新旧自动检查全部通过。
- 使用官方 Google Chrome 完成真实页面验证。
- 仅将本任务相关文件提交并推送至官网仓库 `master`。
