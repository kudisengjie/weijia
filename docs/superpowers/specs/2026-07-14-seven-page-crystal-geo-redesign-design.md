## 1. 设计结论

本次改版以用户提供的七张页面效果图作为高保真布局蓝本，以三个参考视频作为运动语言，以第八张透明机器人图片作为“关于我”页面头像来源。

七张效果图决定页面结构、视觉密度、玻璃材质、模块层级和组件外观。视频一负责滚动叙事、卡片分层和章节衔接；视频二负责水晶折射、玻璃形变、卡片聚合和磁吸反馈；视频三负责空间透视、鼠标视差和首屏主体的镜头感。

现有中文与英文内容、文章 URL、品牌事实、FAQ、结构化数据和爬虫入口继续使用。图片中的演示数字、示例标题和示例日期不得覆盖现有真实内容。

网站继续采用多页面静态架构。首页负责品牌展示和内容入口，完整内容通过真实链接进入独立页面。所有核心文字在初始 HTML 中输出，Canvas 与 WebGL 只负责装饰和 3D 水晶。

## 2. 目标与边界

### 2.1 业务目标

1. 把官网从文字型个人站升级为具备明确品牌记忆的 GEO 专业网站。
2. 让用户在首屏五秒内理解“炜佳导做 GEO 优化与 AI 可见性增长”。
3. 让用户通过首页、博客、指南、策略中心和 FAQ 快速进入对应内容。
4. 保留现有 GEO、SEO 与 AI 抓取能力，不因动态改版损失可索引内容。
5. 将微信与电话咨询设计为清晰的转化路径。
6. 建立可复用的玻璃组件、动效令牌和页面模板，避免每个页面独立堆样式。

### 2.2 视觉目标

1. 使用冰晶白、品牌蓝、折射青和微量折射紫形成统一视觉。
2. 首屏水晶具备透明体积、边缘高光、空间悬浮和光线折射。
3. 动态服务于层级、反馈和页面叙事，不干扰阅读。
4. 桌面端接近效果图的结构比例，移动端按内容优先顺序重排。
5. “关于我”页面使用本次提供的透明机器人原图作为主要头像。

### 2.3 非目标

1. 不把整站改成单页应用。
2. 不把正文、导航或链接绘制到 Canvas。
3. 不把七张效果图作为整页背景图上线。
4. 不复制效果图中的演示数据。
5. 不新增与现有业务无关的社区、会员、支付或后台功能。
6. 不为了动画重写现有全部文章内容。

| `--crystal-surface-strong` | `rgba(255,255,255,.84)` | 导航、正文主卡 |
| `--crystal-ink` | `#07152E` | 标题与正文 |

| `--crystal-blue` | `#2168FF` | 链接、选中和 CTA |
| `--crystal-cyan` | `#70D7FF` | 水晶边缘高光 |

| `--crystal-focus` | `#125BFF` | 键盘焦点 |

正文与背景对比度不低于 4.5:1。大字号标题不低于 3:1。折射色不承担正文信息。

### 5.2 字体与字号

中文优先使用系统字体栈：`PingFang SC`、`Microsoft YaHei`、`Noto Sans SC`、sans-serif。

| 层级 | 桌面 | 移动 | 行高 |
|---|---:|---:|---:|
| 首页主标题 | 56–68px | 38–44px | 1.08 |
| 页面主标题 | 48–56px | 34–40px | 1.12 |
| 区块标题 | 28–36px | 24–30px | 1.2 |
| 卡片标题 | 18–22px | 17–20px | 1.35 |
| 正文 | 16–18px | 16px | 1.75 |
| 元信息 | 13–14px | 13px | 1.5 |

### 5.3 网格与间距

1. 桌面最大内容宽度 1440px，常规内容宽度 1200px。
2. 桌面采用 12 栏网格，平板采用 8 栏，移动端采用 4 栏。
3. 主要断点为 1440、1200、992、768、576 和 375px。
4. 区块垂直间距桌面 80–120px，移动端 48–72px。
5. 卡片圆角使用 18、24 和 32px 三档。
6. 正文阅读宽度控制在 720–780px。

### 5.4 玻璃材质

玻璃卡片由半透明底色、1px 边缘光、顶部内高光和低强度蓝紫阴影组成。默认模糊 16px，重要浮层最高 24px。移动端和低性能模式降低模糊，避免 GPU 过载。

悬停反馈固定为：上浮 4–6px、最大倾斜 3 度、边缘高光扫过一次、持续 220–320ms。

## 6. 3D 水晶与视频动效映射

### 6.1 水晶材质

1. 透明体积与环境折射。
2. 青蓝边缘高光。
3. 少量紫色内部散射。
4. 受控色差，不影响文字清晰度。
5. 基于鼠标或设备方向的轻量视差。
6. 6–8 秒一轮的慢速悬浮。

### 6.2 三个视频的使用边界

| 视频特征 | 站内实现 | 禁止事项 |
|---|---|---|
| 视频一的滚动叙事 | 区块进入、卡片分层、首尾衔接 | 不制造横向滚动陷阱 |
| 视频二的水晶与玻璃重组 | 首屏水晶、平台切换、CTA 反馈 | 不对所有卡片使用高成本折射 |
| 视频三的空间镜头 | 首屏主体视差、背景碎片与纵深 | 不让主体遮挡标题和导航 |

### 6.3 通用动效令牌

| 动效 | 时长 | 缓动 |
|---|---:|---|
| 标题进入 | 500–800ms | `cubic-bezier(.22,1,.36,1)` |
| 卡片交错进入 | 420–650ms | `ease-out` |
| 卡片悬停 | 220–320ms | `ease-out` |
| 平台内容切换 | 300–450ms | `ease-in-out` |
| FAQ 展开 | 260–340ms | `ease-out` |
| 路由离场提示 | 180–260ms | `ease-out` |
| 页面入场 | 450–650ms | `ease-out` |
| 空闲悬浮 | 6–8s | `ease-in-out` |

持续动画仅允许出现在首屏主体、少量背景晶体和头像光环。用户滚动到正文后降低首屏动画频率。

## 7. 页面设计

### 7.1 首页

页面顺序：毛玻璃导航、品牌首屏、核心数据、近期文章、AI 平台专题、P.R.I.M.E 方法论、咨询 CTA、页脚。

首屏左侧保留现有品牌主张和说明，右侧建立 AI 水晶主体。三个信息气泡分别承载方法论、可信度和解决方案提示。气泡使用 DOM，位置围绕水晶布局。

进入顺序：

1. 0–300ms 导航淡入。
2. 150–650ms 标题分行上移。
3. 300–1000ms 水晶从模糊凝聚。
4. 650–1300ms 信息气泡展开。
5. 900–1500ms CTA 与辅助说明进入。
6. 1200ms 后进入慢速悬浮。

近期文章只显示标题、分类和日期。平台专题使用可点击卡片。P.R.I.M.E 五张卡按 P、R、I、M、E 顺序出现。底部咨询条使用轻量磁吸和一次波纹反馈。

### 7.2 关于我

首屏左侧显示姓名、定位、核心主张和原有介绍，右侧显示人物身份卡。

本次提供的 `01_meiwenti_transparent.png` 为 1254×1254、32 位 ARGB 透明图片。正式实现将它复制为新的项目资产，不使用仓库现有 455×640 旧版机器人图代替。

头像规则：

1. 桌面人物卡显示牛仔帽、机器人上半身、竖起大拇指和部分“没问题！”底部字样。
2. 水晶圆环在头像后方慢速旋转，机器人本体只做 6 秒轻微悬浮。
3. 帽檐、耳侧与胸口蓝灯产生低频高光。
4. 鼠标悬停时人物前移 8px，圆环反向旋转 3 度。
5. 点击人物卡打开完整头像预览，保留完整“没问题！”字样。
6. 移动端裁切为头部和手势，完整图片通过点击查看。
7. `alt` 为“炜佳导 GEO 的机器人形象，戴牛仔帽并竖起大拇指”。

页面后续依次为“我是谁”、能力标签、P.R.I.M.E 时间轴、服务方式、合作流程和咨询入口。现有个人事实和方法论内容不得被示例稿替换。

### 7.3 行业博客

首屏使用 BLOG 玻璃板、笔和小型晶体构成视觉主体。列表页只显示标题、日期、分类和进入箭头。

左侧筛选包括标签、时间和标题搜索。筛选状态同步到 URL 查询参数。用户刷新、返回或分享链接时恢复相同状态。

结果变化采用淡出、位置重排和淡入，不使用破坏滚动位置的无限滚动。加载更多必须保留标题占位和焦点位置。

右侧专题卡链接到现有平台文章或指南页。移动端筛选器折叠为抽屉，文章列表置于专题之前。

### 7.4 GEO 指南

首屏使用 GEO 六边形水晶。页面依次显示现有基础说明、E-E-A-T 或原则卡、核心价值、GEO/SEO 对比、章节导航、相关指南和策略中心 CTA。

四张原则卡每张间隔 100ms 进入。GEO/SEO 对比采用真实可访问的分段控件。桌面左侧章节导航吸顶，移动端改为横向可滚动目录。

### 7.5 GEO 策略中心

首屏使用指南针水晶。平台标签使用现有内容中真实存在的平台和文章，不强制复制效果图的平台数量。

平台切换规则：

1. 选中卡片放大至 1.03。
2. 指南针朝向选中平台。
3. 矩阵对应列淡入并上移。
4. 平台标识同步到 URL 查询参数。
5. 会话中记忆上次选择。
6. 键盘 Enter 与 Space 可触发切换。

P.R.I.M.E 路径按时间线点亮。连接线只使用轻量 SVG 或 CSS 动画，不引入第二个 3D 场景。

### 7.6 常见问题

首屏使用 FAQ 水晶和关键词搜索。主体为左侧分类、中间手风琴和右侧咨询卡。

搜索在现有问题与答案中执行，命中词使用品牌蓝高亮。分类和当前问题同步 URL 锚点。通过外部链接进入某个问题时，页面自动定位并展开。

同一分类默认展开一个问题。手风琴支持键盘操作、内容自适应高度和 `aria-expanded`。搜索无结果时显示全部问题入口和咨询方式。

### 7.7 文章详情

文章页保持阅读优先。标题区包含面包屑、标题、日期、分类、阅读时间、收藏或分享入口和主题水晶。

正文结构不改写。顶部阅读进度、右侧吸顶目录、数据卡、引用块、相关文章和咨询卡作为增强层。

目录依据正文现有标题生成。滚动时更新当前章节与 URL 锚点。图片、引用和数据卡进入视口时只播放一次动画。相关文章只显示标题和必要元信息，不复制正文摘要。

### 7.8 品牌事实与机器入口

`brand-facts.html` 使用相同导航、字体、颜色和卡片系统，关闭 3D 水晶。该页继续提供清晰的人类可读品牌事实，同时保持结构化输出。

`llms.txt`、Sitemap、robots 与爬虫后台不加入视觉依赖。

## 8. 组件系统

1. `CrystalNav`：导航、当前页、语言与移动菜单。

3. `GlassCard`：基础玻璃表面与悬停反馈。
4. `CrystalButton`：主次按钮、磁吸和加载状态。
5. `StatCard`：图标、数值、单位和说明。
6. `ArticleRow`：标题、日期、分类和箭头。
7. `PlatformTabs`：平台切换、URL 状态和键盘操作。
8. `PrimeTimeline`：P.R.I.M.E 五步方法论。
9. `FaqAccordion`：问题状态与可访问交互。
10. `ReadingProgress`：文章进度与章节状态。
11. `ConsultPanel`：微信、电话和在线咨询。
12. `RobotAvatar`：机器人头像、光环、预览和移动裁切。
13. `MotionGate`：设备能力、减少动态与 WebGL 降级。

公共组件使用语义类名和 `data-component` 标识。页面只组合组件，不复制组件内部逻辑。

## 9. 技术架构

### 9.1 现状

当前站点是静态 HTML、单一 `style.css`、`script.js` 和 `i18n.js`。主样式约 143KB，国际化文件约 157KB，页面已包含 canonical、结构化数据、文章 Sitemap 和机器入口。

### 9.2 改造方式

1. 保留静态多页面输出。
2. 使用 Vite 只做前端资产构建，不建立客户端路由。
3. 3D 使用 Three.js，滚动编排使用 GSAP 与 ScrollTrigger。
4. 每个页面只加载所需模块。
5. 首屏 3D 失败时切换到预渲染水晶图或 CSS 渐变。
6. 长正文页不加载 Three.js，除非标题区明确需要轻量水晶。

### 9.3 目标文件边界

实施计划应将现有超大样式拆分为：

- `src/styles/tokens.css`
- `src/styles/base.css`
- `src/styles/components.css`
- `src/styles/motion.css`
- `src/styles/pages/home.css`
- `src/styles/pages/profile.css`
- `src/styles/pages/blog.css`
- `src/styles/pages/guide.css`
- `src/styles/pages/strategy.css`
- `src/styles/pages/support.css`

构建结果仍输出站点可直接部署的 HTML、CSS、JS 和图片资源。

### 9.4 数据与状态

博客筛选、平台选择、FAQ 问题和文章章节写入 URL。仅视觉偏好和会话内平台选择可写入本地存储。正文数据不依赖浏览器存储。

### 9.5 错误处理

1. WebGL 创建失败时加载静态水晶后备图。
2. 动效库加载失败时保留完整布局和链接。
3. 筛选脚本失败时显示全部文章。
4. FAQ 脚本失败时所有答案保持可读。
5. 头像优化格式失败时回退到原始 PNG。
6. 第三方资源不得成为首屏渲染依赖。

### 10.4 设计到代码

站点使用原生 HTML、CSS 与 JavaScript，Code Connect 标签使用 `Javascript`。组件节点映射到对应源文件和 CSS 类。每个关键组件在 Figma Handoff 页标明 DOM 语义、状态、断点、动效时长与降级行为。

## 11. 响应式与设备分级

### 11.1 旗舰模式

桌面独立显卡或高性能设备启用完整水晶折射、粒子、鼠标视差和卡片高光。

### 11.2 标准模式

普通电脑和平板降低折射采样、粒子数、阴影层级和 DPR。卡片交互与主要首屏动画保留。

### 11.3 轻量模式

中低端手机关闭持续鼠标视差，使用简化水晶材质，背景粒子减少到 250 个以内。

### 11.4 静态模式

WebGL 不可用、低电量策略或 `prefers-reduced-motion: reduce` 时使用静态水晶、基础淡入或无动画布局。

## 16. 测试与验收

### 16.1 内容与链接

1. 现有文章、FAQ、品牌事实和核心文案完整保留。
2. 导航、卡片、相关文章和 CTA 使用真实链接。
3. 所有 canonical、Sitemap 和内部链接可解析。
4. 中英文切换不丢失页面结构。

### 16.2 动态

1. 七类页面符合参考图的模块顺序和视觉比例。
2. 首屏水晶具备折射、悬浮和受控视差。
3. 动效关闭后布局完整。
4. 动画不阻塞点击、滚动和浏览器返回。

### 16.3 头像

1. 关于我使用用户本次提供的 1254×1254 透明机器人原图。
2. 桌面、移动和完整预览状态均无裁切错误。
3. AVIF、WebP 失败时回退 PNG。
4. 透明边缘无黑边和白边。

### 16.4 GEO 与抓取

1. 关闭 JavaScript 后核心内容仍在页面中。
2. 爬虫可获取标题、正文、FAQ 和结构化数据。
3. Canvas 中不存在机器必须读取的文字。
4. `robots.txt`、`llms.txt` 和两个 Sitemap 校验通过。

### 16.5 性能与兼容性

1. 通过 Lighthouse 与真实浏览器性能采样。
2. 验证 Chrome、Edge、Safari 和 Firefox 当前稳定版。
3. 验证 1440、1200、992、768、576 与 375px。
4. 验证 WebGL 失败、减少动态、低性能和无 JS 模式。

### 16.6 回归

运行仓库现有验证脚本，并为新增组件补充单元或 DOM 测试、Playwright 页面测试、视觉截图基线和爬虫内容一致性测试。
