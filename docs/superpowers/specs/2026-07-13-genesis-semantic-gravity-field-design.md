# GENESIS · 语义引力场整站动态改版设计规范

**状态：** 已获用户确认

**日期：** 2026-07-13

**站点：** https://www.lxue.xin

**设计范围：** 首页、核心信息页、博客与文章模板、FAQ、品牌事实入口、全局导航与转场

## 1. 设计结论

整站采用「GENESIS · 语义引力场」方向。

首页是一座可交互的 3D 水晶知识中枢。水晶代表 SGFE 语义引力场，轨道节点承载站内入口，P.R.I.M.E 五步方法论成为水晶的五个受光面。用户通过真实链接进入独立内容页。现有正文、品牌事实、FAQ、文章和结构化数据继续使用原始 HTML 输出。

三支参考视频分别承担明确职责：

- 第一支提供全屏构图、镜头推拉、章节转场和无缝回环。
- 第二支提供透明体积、折射、边缘高光、玻璃导航坞、卡片重组和水晶按钮形变。
- 第三支提供大型 3D 主体、近大远小的空间比例和鼠标/滚动驱动的相机变化。

整站保持明亮的冰白、品牌蓝、折射青和能量紫体系，不采用黑底赛博朋克风格，也不以定制 3D 人物作为主角。

## 2. 目标与非目标

### 2.1 目标

1. 用户进入首页后 5 秒内识别出 GEO、AI 搜索与语义引力场的品牌主题。
2. 首页只提供品牌主张、证据和入口，不承载长篇正文。
3. 用户通过点击进入独立页面阅读现有内容。
4. 所有可抓取文字、链接、标题和结构化数据保留在初始 HTML 中。
5. 首页获得接近参考视频的材质、镜头与形变质量。
6. 中端手机、减弱动态模式和无 WebGL 环境仍能完整浏览与导航。
7. 动效服务于导航、解释、证据展示和咨询转化。

### 2.2 非目标

- 不重写现有文章和方法论正文。
- 不把站点改成单页应用。
- 不使用 Canvas 绘制正文、导航文字或关键链接。
- 不为 AI 爬虫输出与用户不同的隐藏内容。
- 不在每篇文章中加载 Three.js。
- 不采用全站滚动劫持。
- 不制作高成本 3D 人物作为品牌核心。

## 3. 已审计的现状

当前站点采用静态 HTML 多页面结构，由一份大型 `style.css`、`script.js` 和 `i18n.js` 提供样式、交互和中英文内容。首页没有 Canvas 或 WebGL，现有动效集中在淡入、位移、悬浮和导航模糊。

公开内容包含：

- 7 个核心入口：首页、关于我、品牌事实、行业博客、GEO 指南、策略中心、常见问题。
- 23 篇独立文章，覆盖基础认知、技术原理、P.R.I.M.E、SGFE、平台差异、行业差异、指标、Schema、E-E-A-T、合规、知识图谱、AI Agent、服务商选型和商业闭环。
- `robots.txt`、`llms.txt`、主 sitemap、文章 sitemap 和 JSON-LD。

现有静态多页面结构与 GEO 目标相符。设计只增加渐进增强层，不更换内容输出方式。

## 4. 视觉系统

### 4.1 色彩

| 用途 | 色值 |
|---|---|
| 冰白背景 | `#F7FAFF` |
| 深海军蓝 | `#07172F` |
| 品牌蓝 | `#2D6BFF` |
| 折射青 | `#88ECFF` |
| 能量紫 | `#8B7CFF` |
| 低对比网格 | `rgba(48, 92, 150, 0.04)` |

### 4.2 水晶材质

水晶需要同时具备透明体积、环境折射、白色边缘高光、低强度薄膜虹彩和蓝色环境阴影。材质不能退化成带透明度的普通卡片。

水晶核心采用多面非对称晶体，不使用常见球体或标准六边形。五个主要受光面分别对应 P、R、I、M、E。第六个内部核心代表 SGFE。

### 4.3 排版与空间

- 首屏标题保持大字号和短行宽，与 3D 主体形成左右张力。
- 中文正文继续采用清晰黑体体系，英文和数字采用几何无衬线字体。
- 首页留白占主导，3D 主体可占桌面视口宽度的 38% 至 48%。
- 内页正文维持舒适阅读宽度，桌面端正文列控制在约 760 至 860px。
- 光效只用于当前焦点、入口状态和咨询转化。

## 5. 信息架构

### 5.1 首页主要入口

| 节点 | 标签 | 目标 |
|---|---|---|
| 01 | 关于炜佳导导 | `/profile.html` |
| 02 | P.R.I.M.E 方法论 | `/profile.html#prime`；实现时在现有 `.prime-block` 上增加 `id="prime"` |
| 03 | GEO 策略中心 | `/insights.html` |
| 04 | GEO 完整指南 | `/geo-guide.html` |
| 05 | 行业知识库 | `/blog/` |
| 06 | GEO 问答库 | `/support.html` |
| AI | AI 数据索引 | `/brand-facts.html` |
| CTA | 开启 AI 可见度诊断 | 现有联系信息对应的可访问入口 |

其余入口沿用现有独立页面 URL，不新增同义内容页。

### 5.2 HTML 要求

每个视觉节点必须对应真实 `<a href>`。链接文字和一行摘要在 DOM 中可见、可聚焦、可被爬虫读取。Canvas 只绘制水晶、粒子、轨道和空间晶片。

`<noscript>` 状态提供标准入口列表。低性能模式复用同一组 DOM 链接，不创建另一套内容。

## 6. 首页镜头脚本

首页使用正常文档滚动和 Sticky 3D Canvas。滚动条由浏览器控制，滚动进度驱动相机和物体时间线。

| 阶段 | 滚动区间 | 画面与行为 | 交互出口 |
|---|---:|---|---|
| Arrival | 0%–8% | 失焦光斑在 600–900ms 内聚合成水晶，标题同步显现 | 两个首屏 CTA |
| Field | 8%–26% | 六个内容节点沿轨道展开，水晶产生低角度视差 | 六个主要入口 |
| Proof | 26%–43% | 380%、-57%、56 家企业等现有数据转成证据晶片经过镜头 | 品牌事实、策略中心 |
| Method | 43%–62% | P、R、I、M、E 五个受光面依次聚焦 | 方法论对应章节 |
| Knowledge | 62%–80% | 文章卡片由分散状态堆叠并收束为知识库入口 | 博客与文章入口 |
| Loop | 80%–91% | 卡片重新融入水晶，场景回到核心构图 | 全部入口恢复 |
| Convert | 91%–100% | 水晶压缩成透明胶囊按钮，显示“开启 AI 可见度诊断” | 联系入口 |

### 6.1 空闲状态

- 水晶使用低幅度呼吸与高光移动，不做持续大幅旋转。
- 桌面鼠标只产生 2–3° 视差。
- 用户停止操作后，粒子和相机保持低成本循环。
- 页面不可见时暂停 `requestAnimationFrame`。

### 6.2 页面切换

支持 View Transitions 的浏览器播放 450–650ms 的折射收束转场。其他浏览器直接进行标准多页面跳转，可选用短时 CSS 遮罩。真实链接、历史记录和后退行为不依赖转场脚本。

## 7. 全局导航

桌面端使用右侧纵向透明导航坞，借鉴第二支视频的展开式玻璃工具条。默认显示短标记，聚焦或悬停后展开文字。移动端改为底部横向胶囊导航，不依赖 hover。

导航坞包含首页、关于、策略、指南、知识库、问答、AI 数据和咨询入口。当前页面、键盘焦点和悬停状态必须可区分。

## 8. 页面级设计

### 8.1 关于我

- 使用现有肖像素材制作二维切片与轻视差，不制作 3D 人物。
- P.R.I.M.E 表格升级为空间时间线，正文仍在 DOM 中按原顺序出现。
- SGFE 组件使用二维轨道图或轻量 CSS/SVG 关系图。
- 联系信息保留真实文本和链接。

### 8.2 品牌事实

- 视觉主题为“AI 数据保险库”。
- 身份、机构、方法论、服务和数据事实按字段组展示。
- 使用扫描线、字段连接和更新时间反馈，不加载重型 3D。
- 页面保持公开可读，不隐藏在后台或仅向爬虫开放。

### 8.3 GEO 策略中心

- 四类 AI 平台成为可切换的轨道节点。
- 点击节点更新对应的 DOM 说明区域，并维持可分享的锚点。
- 诊断、内容、信任和复盘交付物形成清晰流程。

### 8.4 GEO 指南

- 五项原则和五步实施路径使用滚动点亮时间线。
- GEO/SEO 对照表保持 HTML table，并提供移动端横向滚动或卡片化可读布局。
- 实操清单使用可勾选的视觉状态，勾选状态不改变原文。

### 8.5 博客与文章

- 博客首页以空间卡片书架组织文章，筛选和搜索使用标准 DOM 控件。
- 卡片悬停允许轻微倾斜与层级变化。
- 文章正文不加载 Three.js，只保留标题入场、阅读进度、悬浮目录、表格和引用块动效。
- 文章 URL、canonical、发布日期、作者、正文和 Article Schema 保持不变。

### 8.6 FAQ

- 页面使用可搜索的水晶问答控制台。
- 分类切换和手风琴展开具备键盘操作与 ARIA 状态。
- FAQPage Schema 与可见问答文本保持一致。

## 9. 技术架构

### 9.1 页面架构

继续使用静态多页面网站。Vite 只负责编译和压缩 CSS、JavaScript、Three.js 模块与 3D 资产。每个页面保持独立 HTML 和真实 URL。

### 9.2 模块边界

| 模块 | 职责 | 加载范围 |
|---|---|---|
| Core UI | 导航、焦点、菜单、公共 DOM 行为 | 全站 |
| Motion Preferences | 减弱动态、Save-Data、设备能力分级 | 全站 |
| Page Transition | 渐进式多页面折射转场 | 全站 |
| Home Scene | Three.js 场景、相机、水晶、轨道、晶片 | 仅首页动态加载 |
| Home Timeline | 滚动进度与镜头/物体状态映射 | 仅首页 |
| Content Motion | 内页观察器、目录、进度、轻动效 | 对应内页 |
| Analytics | 入口聚焦、打开、咨询和性能等级事件 | 全站 |

### 9.3 资产格式

- 水晶与节点使用 GLB。
- 几何体使用 Meshopt 或 Draco 压缩。
- 环境图与纹理使用 KTX2；备用视觉使用 AVIF/WebP。
- 3D 资产和 Three.js 不进入普通文章页面的初始包。

## 10. 设备分级与降级

### 10.1 旗舰模式

启用完整折射、虹彩、受控景深、环境反射和粒子。

### 10.2 标准模式

减少粒子，关闭实时景深，简化折射采样并降低 DPR。

### 10.3 静态模式

使用水晶 AVIF/WebP 海报、CSS 光效和相同的 DOM 链接。以下情况直接使用静态模式：

- WebGL 初始化失败。
- 浏览器报告 `prefers-reduced-motion: reduce`。
- 用户启用 Save-Data。
- 设备能力或启动帧率低于安全阈值。

运行中发生 WebGL context loss 时，系统先尝试一次恢复。恢复失败后切换静态模式，并保留用户当前滚动位置和全部链接。

## 11. 性能预算

| 指标 | 上线门槛 |
|---|---:|
| 移动端 LCP | ≤ 2.5s，目标 2.2s |
| INP | ≤ 200ms |
| CLS | ≤ 0.1 |
| 首页首屏 JavaScript | ≤ 220KB gzip |
| 普通内页 JavaScript | ≤ 65KB gzip |
| 水晶与节点 GLB | ≤ 1.2MB |
| 首屏纹理 | ≤ 512KB |
| 首页首屏总资源 | ≤ 1.8MB |
| 桌面帧率 | 目标 55–60 FPS |
| 中端手机帧率 | 不低于 40–45 FPS |
| Draw Calls | ≤ 40 |
| 三角面 | ≤ 120,000 |
| DPR | 手机最高 1.5，桌面最高 2 |
| 粒子数 | 桌面 ≤ 800，手机 ≤ 250 |

若视觉效果与性能预算冲突，先降低粒子、景深、折射采样和 DPR，不删除真实链接或正文。

## 12. GEO 与可访问性约束

1. 首页保留唯一 H1、品牌定位短文、入口标签和一行摘要。
2. 所有主要页面入口使用真实链接。
3. 保留 Organization、Person、WebSite、Article、FAQPage 等既有 JSON-LD，并验证可见内容与结构化数据一致。
4. 保留 `robots.txt`、`llms.txt`、主 sitemap 和文章 sitemap。
5. JavaScript 关闭时仍可访问全部主要页面和文章。
6. 不使用透明文字、屏外堆叠或爬虫专用内容。
7. 所有交互支持键盘、触摸和可见焦点。
8. 颜色对比满足 WCAG AA。
9. 减弱动态模式关闭相机推进、粒子和形变，保留短淡入或完全静态状态。
10. Canvas 需要可访问名称，但关键语义位于相邻 DOM 中。

## 13. 数据流与交互状态

首页 DOM 是链接、标题、摘要和 CTA 的唯一数据源。3D 场景读取预定义节点标识，将视觉物体与 DOM 节点建立一对一关系。

交互流程：

1. 页面先渲染 HTML 与备用视觉。
2. 能力检测选择画质等级。
3. 首页动态导入 3D 模块。
4. 3D 模块加载成功后替换备用视觉，但不替换 DOM 导航。
5. 滚动进度更新镜头与物体状态。
6. 指针或键盘聚焦 DOM 链接时，高亮对应 3D 节点。
7. 点击链接后播放可选转场并进行标准页面导航。

3D 资源加载失败、超时或上下文丢失时，DOM 入口保持可用。

## 14. 分析事件

仅记录不含个人敏感信息的交互事件：

- `portal_focus`
- `portal_open`
- `prime_step_open`
- `article_cluster_open`
- `diagnosis_cta_open`
- `quality_tier_selected`
- `webgl_fallback`

事件用于判断用户是否看懂入口、哪些内容最受关注，以及低端设备降级比例。

## 15. 测试与验收

### 15.1 功能测试

- 六个主要入口、AI 数据入口和咨询入口均可通过鼠标、键盘和触摸打开。
- 页面后退恢复合理滚动位置。
- View Transitions 不可用时正常导航。
- WebGL 初始化失败和 context loss 会切换备用视觉。

### 15.2 抓取测试

- 使用原始 HTTP 响应检查 H1、摘要、链接、canonical 和 JSON-LD。
- 禁用 JavaScript 后遍历核心页与文章。
- 验证两个 sitemap、`robots.txt` 和 `llms.txt`。
- 校验 Article、FAQPage、Person、Organization 数据与可见文本一致。

### 15.3 视觉与动态测试

- 对首页七个镜头阶段建立截图基线。
- 录制桌面、移动端、减弱动态和静态模式。
- 核对水晶透明体积、边缘高光、折射、卡片重组和按钮形变。
- 检查文字与 3D 主体在常见宽度下不重叠。

### 15.4 性能测试

- 使用移动 4G 条件运行 Lighthouse 与真实浏览器性能测试。
- 记录 LCP、INP、CLS、资源大小、帧率、Draw Calls 和三角面。
- 在中端 Android、iPhone Safari、桌面 Chrome/Edge/Firefox/Safari 验证。

### 15.5 上线验收

- 首屏在 5 秒内表达 GEO 与 AI 搜索主题。
- 用户能在 5 秒内找到内容入口。
- 首页不出现长篇文章墙。
- 23 篇文章保持独立 URL 和完整正文。
- 关闭 JavaScript 后导航、品牌摘要和内容链接仍存在。
- 移动端不依赖 hover。
- 性能指标达到本规范预算。
- 正式版本具备旧首页回滚路径。

## 16. 发布策略

1. 先在独立预览环境制作水晶材质和首屏镜头原型。
2. 原型通过材质、帧率和移动端降级验证后，完成首页全时间线。
3. 接入全局导航和页面转场。
4. 分批升级核心页、博客、FAQ 和文章模板。
5. 完成抓取、无障碍和性能审计。
6. 灰度上线并观察入口点击、咨询、性能等级和降级事件。
7. 保留旧版首页资产，在上线观察期内支持快速回滚。

## 17. 十轮设计复盘结论

1. 将水晶从装饰升级为 SGFE 品牌载体。
2. 将三支视频拆分为材质、镜头和滚动节奏三个职责。
3. 将首页收敛为六个用户入口、一个 AI 数据入口和一个咨询入口。
4. 为每段动效指定导航、解释、证据或转化任务。
5. 使用常驻导航坞和最终咨询按钮保护转化路径。
6. 将语义、链接和正文留在 HTML 中。
7. 将重 3D 限定在首页，文章页优先阅读。
8. 使用三级画质和严格性能预算控制移动端成本。
9. 为触摸、键盘和减弱动态模式提供完整操作路径。
10. 使用静态多页面渐进增强、灰度发布和回滚降低上线风险。

本规范锁定设计方向。任何降低水晶材质质量、隐藏真实链接、将站点改成纯 Canvas、在文章页加载重 3D 或取消性能降级的实现都不符合设计要求。
